# 第三课：升级视觉编码器——标准化、ResNet18与预训练

本课接着[第二课](MINI_VLA_LESSON_02.md)。M2已经能根据当前图像、指令和本体状态，一次预测10步动作，执行前5步后重新观察。M3保留这套动作流程，研究视觉输入和视觉编码器的变化。

阅读顺序：改动位置 → 三组对照 → RGB标准化 → ResNet内部结构 → 预训练与微调 → 真实实验结果 → 修改你的架构图。

本课对应已完成的2026-10-19历史实验，只使用Spatial的384条训练示范、48条离线验证示范及28项词表。不要把后续四套联合训练的1506/187示范、71项词表或最终2000集评测混入本课。这里介绍课程和既有证据，不启动新的实验。

## 1. 从M2出发：这次改哪里

先把M2主线写出来：

```text
当前外部图像 ─┐
              ├─ 共享小CNN ─ 两个256维视觉特征 ─ 拼接512维 ─┐
当前腕部图像 ─┘                                          │
当前文字指令 ─ 词Embedding + 有效词平均 ─ 64维 ───────────┼─ 拼接640维
当前8维状态 ─ 标准化 + 状态MLP ─ 64维 ───────────────────┘
                                                            ↓
                                                MLP：640→512→256→128→70
                                                            ↓
                                                   [B,10,7]动作块
                                                            ↓
                                               执行前5步，再读取新观测
```

M3修改的是左上方“图像怎样变成256维特征”。它仍然输出每张图256维，因此后面可以继续使用原来的512维双相机特征、640维融合输入和70维动作输出。

这叫保持模块接口一致：模块内部可以换，输入和输出的约定保持清楚，其他模块就不必跟着改。

本轮固定K=10、H=5。K是动作预测长度，H是执行前缀长度，都不是视觉特征维度。

## 2. 为什么M3有三组配置

如果从小CNN直接换到预训练ResNet，并且同时增加图像标准化，即使成绩上升，也不知道哪项变化起作用。因此本项目实际做了三组新配置，并复用已验收的M2-H5基线。

| 配置 | RGB输入处理 | 视觉结构 | 初始化 |
|---|---|---|---|
| M2-H5基线 | 除以255 | 三层小CNN | 随机 |
| M3 `tiny_norm` | 除以255，再按RGB通道标准化 | 同一个三层小CNN | 随机 |
| M3 `resnet_random` | 同上 | ResNet18主干 + 自定义投影 | 随机 |
| M3 `resnet_pretrained` | 同上 | 与随机ResNet组相同 | 主干加载ImageNet权重，投影随机 |

沿着表格相邻比较：

1. **M2 → tiny_norm**：检验新增RGB标准化的影响。
2. **tiny_norm → resnet_random**：检验视觉结构和容量这一组变化的影响；包括更深网络、残差连接、BatchNorm、通道数和投影参数量，并非单独检验残差连接。
3. **resnet_random → resnet_pretrained**：结构相同，主要比较主干初始化；输入处理、投影及非视觉模块的初始参数保持匹配。

这里“控制变量”指尽量明确每次比较改变了什么，不表示一个训练种子的结果就能证明普遍因果结论。

## 3. 图像已经除以255，为什么还要标准化

这是两个连续的操作。

第一步把uint8像素转换为浮点数并缩放：

\[
x=\frac{p}{255}.
\]

原来像素在0～255，处理后在0～1。第二步再对R、G、B三个通道分别做：

\[
x'_c=\frac{x_c-\mu_c}{\sigma_c}.
\]

本项目M3固定使用：

| 通道 | 均值 \(\mu\) | 标准差 \(\sigma\) |
|---|---:|---:|
| R | 0.485 | 0.229 |
| G | 0.456 | 0.224 |
| B | 0.406 | 0.225 |

例如一个R通道像素值为128：

```text
128 ÷ 255 ≈ 0.50196
(0.50196 − 0.485) ÷ 0.229 ≈ 0.0741
```

同一个128，放在G或B通道，会因为均值和标准差不同而得到不同数值。标准化后可以为负，也可以大于1；此处不把结果裁剪回0～1。

这些常量对应我们选择的ImageNet预训练权重的输入约定。标准化不会自动让机器人图像的实际均值变成0、标准差变成1，因为机器人图像分布不一定和预训练图像相同。官方权重的默认分类推理还包含224中心裁剪；本项目为保持M2对照，仍用128双线性缩放，不做中心裁剪或数据增强。[Torchvision 0.22的权重与预处理说明](https://docs.pytorch.org/vision/0.22/models/generated/torchvision.models.resnet18.html)

不要把下面三类统计混淆：

| 数据 | 本项目统计来源 | 作用位置 |
|---|---|---|
| M3图像RGB | 固定ImageNet常量 | 进入视觉主干前 |
| 机器人状态 | 本项目训练示范 | 进入状态MLP前 |
| 专家动作 | 本项目训练示范 | 训练标签标准化，输出时反标准化 |

离线训练的图像缓存是uint8，`experiment_m3_v1.py`的`inputs`负责除以255；在线接口的`image_tensor`负责除以255。随后两条路径都进入模型内部的`RGBStandardize`，因此各标准化一次，不能在外部再重复减均值、除标准差。

## 4. `RGBStandardize`怎样实现

实际代码见[visual_model_v1.py](../mini_vla/visual_model_v1.py)：

```python
self.register_buffer('mean', torch.tensor([.485,.456,.406]).reshape(1,3,1,1))
self.register_buffer('std', torch.tensor([.229,.224,.225]).reshape(1,3,1,1))

def forward(self, image):
    return (image - self.mean) / self.std
```

输入是`[N,3,128,128]`，统计量是`[1,3,1,1]`。广播会让每个通道的所有像素使用对应的一个均值和标准差；统计量不会把通道或图像混在一起平均。

`register_buffer`表示“随模型保存、随模型搬到GPU，但不是优化器要学习的参数”。所以加入这一步不会增加可训练参数量。

`tiny_norm`这一组，就是把原M2视觉编码器套在这一步后面：

```text
[0,1] RGB → 固定通道标准化 → 原小CNN → 256维
```

## 5. ResNet18是什么，主干是什么

这里的ResNet18仍然是卷积网络。它由开头的卷积、若干残差块和原本用于图像分类的末端结构组成。

**主干（backbone）**是提取图像特征的主体。**分类头**把这些特征转换成类别分数。机器人需要生成动作，所以我们取出视觉主干，再接自己的视觉投影与动作预测网络。

本课还会出现两个不同的“头”：

- 视觉投影：把视觉主干特征转换成我们需要的256维接口。
- 动作预测头：根据融合后的视觉、文字、状态预测70个动作分量。

它们不是同一个模块。加载图像分类预训练权重，也不等于已经加载了会控制机械臂的动作模型。

## 6. 残差块内部怎样走

在一个不改变通道数和空间大小的BasicBlock里：

```mermaid
flowchart LR
    X[输入 x] --> C1[3×3卷积]
    C1 --> B1[BatchNorm]
    B1 --> R1[ReLU]
    R1 --> C2[3×3卷积]
    C2 --> B2[BatchNorm]
    B2 --> A[逐元素相加]
    X --> A
    A --> R2[ReLU]
    R2 --> Y[输出 y]
```

把两层卷积这一支记为`F(x)`，则：

\[
y=\operatorname{ReLU}\big(F(x)+x\big).
\]

这条跨过卷积层的支路叫捷径连接或残差连接。可以把它理解成：原特征先沿捷径保留，另一支学习如何修正它。这种结构有利于较深网络的优化，但不保证任意任务的成绩都更好。残差学习的原始动机和实验见[ResNet论文](https://arxiv.org/abs/1512.03385)。

这里是**逐元素相加，不是拼接**。例如两支都是`[N,64,32,32]`，相加后仍是`[N,64,32,32]`，不会变成128个通道。

如果一个块把`[N,64,32,32]`变成`[N,128,16,16]`，原输入就不能直接相加。这时捷径支路也通过`1×1卷积（步长2）+ BatchNorm`，调整为相同形状，再进行相加。

这部分已对照当前环境安装的Torchvision `BasicBlock.forward`核查；在我们的代码中，BasicBlock来自Torchvision，并非本项目重新实现了ResNet论文的所有底层算子。

## 7. BatchNorm和RGB标准化有什么区别

BatchNorm简称BN，位于网络内部。在卷积网络里，训练时通常对某个特征通道在batch和空间位置上的值计算统计量，再进行变换：

\[
y=\gamma\frac{x-\mu_{\mathrm{batch}}}{\sqrt{\sigma^2_{\mathrm{batch}}+\epsilon}}+\beta.
\]

其中`γ、β`是可学习的缩放和平移参数，`ε`是避免除零的小常数。验证/推理时使用保存的运行均值和方差，而不是依赖当前单张图重新估计一套训练batch统计。

| 比较 | RGBStandardize | ResNet内部BatchNorm |
|---|---|---|
| 处理对象 | 原始RGB三个通道 | 中间特征的多个通道 |
| 统计量 | 固定常量 | 训练批次统计及其运行估计 |
| 可学习参数 | 没有 | 有γ、β |
| train/eval行为 | 相同 | 不同 |

`model.train()`和`model.eval()`是模式切换，影响BN等模块；它们本身不执行参数更新，也不等于开启/关闭梯度。更新参数还需要反向传播和`optimizer.step()`。

我们的两路图像沿batch维合并后进入同一个主干，所以训练时同一BN层的统计会覆盖这个合并批次中的两种相机图像，而不是每个相机各有一套BN模块。

## 8. 128×128图像进入ResNet后，尺寸怎样变化

下面用`N`表示进入共享编码器的图像数量。本项目两路相机合批后，`N=2B`。

| 阶段 | 核心操作 | 输出形状 |
|---|---|---|
| 输入 | 已缩放和RGB标准化 | `[N,3,128,128]` |
| 开头卷积 | 7×7，步长2，填充3；BN、ReLU | `[N,64,64,64]` |
| 最大池化 | 3×3，步长2，填充1 | `[N,64,32,32]` |
| layer1 | 2个BasicBlock | `[N,64,32,32]` |
| layer2 | 2个BasicBlock，首块下采样 | `[N,128,16,16]` |
| layer3 | 2个BasicBlock，首块下采样 | `[N,256,8,8]` |
| layer4 | 2个BasicBlock，首块下采样 | `[N,512,4,4]` |

例如开头卷积的空间尺寸：

\[
\left\lfloor\frac{128+2\times3-7}{2}\right\rfloor+1=64.
\]

64个输出通道来自这一层设置了64个卷积滤波器，不是由这个空间尺寸公式算出来的。

“最大池化”在局部窗口取最大值；此前小CNN的“平均池化”取平均值。二者都不需要学习卷积权重，但计算方式不同。

每个BasicBlock有两层主分支卷积，四个stage各有两个块，因此主分支有`1+4×2×2=17`层卷积；原分类模型再加一个全连接层，按惯例称为ResNet18。捷径的投影卷积不包含在这个常用命名计数里。我们的整套M3还包含自定义投影、状态/语言/动作模块，因此不能把整个机器人策略说成“总共18层”。

## 9. 本项目没有使用默认的512维全局池化输出

这是阅读代码和修改架构图时最容易弄错的地方。

原分类ResNet末尾是：

```text
512通道特征图 → 全局平均池化到1×1 → 展平512维 → 分类层
```

而本项目使用：

```python
backbone = nn.Sequential(*list(network.children())[:-2])
projection = nn.Sequential(
    nn.AdaptiveAvgPool2d((4, 4)),
    nn.Flatten(),
    nn.Linear(512 * 4 * 4, 256),
    nn.ReLU(),
)
```

`children()[:-2]`去掉了原来的全局平均池化和分类层。真正的数据流是：

```text
ResNet主干输出 [N,512,4,4]
            ↓ 自适应平均池化到4×4
          [N,512,4,4]
            ↓ 展平
          [N,8192]
            ↓ Linear 8192→256 + ReLU
          [N,256]
```

在固定128输入下，主干已经输出4×4，因此这次自适应池化不再缩小空间尺寸。它明确规定投影入口的网格大小。

`512`表示特征通道数，`4×4`表示每个通道保留16个空间位置，展平后才是`512×4×4=8192`。这是粗空间网格，不是16个已标注物体，也不能把某一维直接命名为“碗的位置”。

视觉投影层单独就有：

\[
8192\times256+256=2,097,408
\]

个可训练参数。较大的投影也是M3容量变化的一部分。

## 10. 两个相机仍然共享一个视觉编码器

```text
外部图像 [B,3,128,128] ─┐
                       ├─ 沿batch维拼接 [2B,3,128,128]
腕部图像 [B,3,128,128] ─┘
                                  ↓
                      RGB标准化 + ResNet主干 + 投影
                                  ↓
                              [2B,256]
                                  ↓ 按相机拆分
                     [B,256]外部 + [B,256]腕部
                                  ↓ 沿特征维拼接
                               [B,512]
```

共享权重不表示两个相机输出相同。它表示使用同一套计算规则，处理不同的输入图像；外部与腕部特征仍按固定顺序保留身份。

后面仍然拼上64维文字特征和64维状态特征，得到`[B,640]`，再通过原M2的MLP输出`[B,10,7]`。

## 11. 预训练、初始化、微调、冻结分别是什么意思

把网络结构理解成计算规则，把权重理解成这些规则中的具体数值。

| 术语 | 在本课中的具体含义 |
|---|---|
| 随机初始化 | 用规定的随机初始化方法设置权重，再从机器人示范中学习 |
| 预训练 | 官方已经在图像分类数据上训练过ResNet权重 |
| 加载预训练初始化 | 将那些已有数值作为本轮机器人训练的起点 |
| 微调 | 在机器人损失下继续更新已加载的权重 |
| 冻结 | 不更新某部分权重，只使用其特征 |

**M3预训练组会微调保留下来的整个视觉主干，并没有把ResNet冻结。** 新视觉投影、语言Embedding、状态MLP、融合及动作头也参与机器人训练。固定RGB统计量仍是buffer；BN的运行统计会按训练模式更新，它们与优化器学习的权重是不同类型的状态。

预训练组的起点是：

```text
ResNet视觉主干：官方ImageNet权重
8192→256视觉投影：随机初始化
语言、状态、融合、动作头：随机初始化
```

原1000类分类头没有进入机器人模型。预训练不是机器人专家动作预训练，也没有让这个模型自动获得大语言模型的理解能力；本课文字分支仍是28项词表的Embedding加均值池化。

代码先调用`resnet18(weights=None)`创建结构，再显式读取已校验的本地权重，避免隐式下载。正式训练初始化时才需要这次加载；从完整机器人检查点恢复时，完整`state_dict`已经包含微调后的主干和投影，不应再用官方权重覆盖它。

随机ResNet组和预训练ResNet组的视觉投影及非视觉初始参数已独立核对一致；预训练主干的初始张量与官方文件匹配，梯度存在且有限，训练后权重确实变化。[已有完整验收](../results/mini_vla_m3_20261019_run3/REVIEWED_REPORT.md)

## 12. 训练样本、标签和损失怎样衔接

M3没有把输入变成多帧视频：仍是一个当前时刻的双相机图像、状态和指令。专家标签仍为当前及后续9步动作，末尾padding仍被mask排除。

```text
当前观测 → 新视觉编码器及原其他模块 → 预测[B,10,7]
专家动作 → 训练侧标准化 ────────────→ 标签[B,10,7]
轨迹末尾有效位置 ─────────────────→ mask[B,10]
                                      ↓
                               masked MSE → backward → step
```

每组均为：

| 设置 | 值 |
|---|---|
| 训练/离线验证示范 | 384 / 48，按整条轨迹划分 |
| 训练/验证帧数 | 46982 / 5988 |
| 训练epoch | 50 |
| batch大小 | 128，保留最后不足一批的样本 |
| 正式优化器更新 | 18400 |
| 优化器 | AdamW，学习率3e-4，weight decay 1e-4 |
| 训练随机种子 | 42，每组从规定的初始参数开始 |
| 训练损失 | 全部有效K10动作位置的标准化MSE |
| 检查点选择 | 完整验证集首动作MSE最低，平局取较早轮次 |
| 闭环执行 | K10/H5，原固定Spatial50 |

三组各自选自己的最佳轮次，不根据闭环成功率换检查点。它们也不是在M2已经训练好的权重上继续训练；继承M2代码结构与接着M2权重训练是两回事。

## 13. 已完成的实验结果

以下为训练报告与已验收闭环结果。MSE保留5位小数；独立CPU复算与记录的差异在原2e-5容差内。

| 配置 | 可训练参数量 | 选中epoch | 验证首动作MSE | 成功/50 | 成功率 | RPC中位延迟 |
|---|---:|---:|---:|---:|---:|---:|
| M2-H5 | 794726 | 14 | 0.36550 | 41 | 82% | 5.316ms |
| M3 tiny_norm | 794726 | 9 | 0.36702 | 36 | 72% | 6.779ms |
| M3 随机ResNet18 | 13781894 | 48 | 0.37528 | 39 | 78% | 7.344ms |
| M3 预训练ResNet18 | 13781894 | 50 | 0.37605 | 44 | 88% | 7.637ms |

可以读出几件事：

1. **加标准化不是必然涨分。** tiny_norm比M2少成功5集；不能把预训练模型的输入习惯当成任何随机小CNN都一定受益的操作。
2. **换成更大的随机ResNet没有超过原M2。** 随机组为39/50，而M2为41/50；因此不能简单说“网络更大所以更好”。
3. **本轮预训练组好于同架构随机组。** 逐场景比较，救回6集、损失1集，净增加5集，即10个百分点。
4. **离线MSE和闭环成功率再次不完全一致。** 预训练组首动作MSE略高于M2，但闭环成功更多；成功还依赖策略产生的状态分布和后续动作。

预训练组相对M2从82%到88%，是**提高6个百分点**，对应净增加3/50；不是增加6个场景。它还增加了约17.34倍的参数量，RPC中位延迟从5.316ms到7.637ms，约高44%。RPC是客户端到服务端的往返耗时，各次实验在共享机器上不同时间运行，不能作为严格同负载速度基准。

预训练对随机组的任务聚类描述性95%区间是[2,18]个百分点；相对M2则为[−6,20]个百分点。只有一个训练种子，而且50集反复用于开发，不能据此宣称已证明独立测试或完整LIBERO提升。这个阶段的证据支持把预训练视觉主干带到M4继续比较，不保证以后每次升级都更好。

选中的预训练检查点恰好是第50轮，只表示这50轮中的最低验证误差在最后一轮；不能据此自动多训练，也不能直接断言已经收敛或一定还会提升。

<details>
<summary>参考答案</summary>

1. 约0.0741；经过通道标准化后不再保证0～1范围。
2. 仍为`[4,64,32,32]`；改变形状时捷径也要用投影调整成`[4,128,16,16]`后才能相加。
3. 本项目保留512通道的4×4网格，展平是`512×4×4=8192`；原全局池化和分类头已移除。
4. 前者保持结构等条件一致，比较主干初始化；后者还同时改变深度、BN、通道数、投影容量等，不能只归因于残差连接。
